# Правила для скриптов поиска и анализа

Правила 8–10 перенесены из скилла `oh-my-god` без изменений. Ссылки «Rule 3.3», «Rule 4» ведут на правила `oh-my-god`.

### 8. Самопроверка инструментов анализа
Любой созданный инструмент анализа (скрипт поиска, линтер, генератор отчётов) должен
пройти самопроверку перед сдачей. Чек-лист:

1. **Запустить на себе** — инструмент не должен находить себя в результатах.
   Пример: `find-variables.sh` не должен показывать `${VAR}` из своего кода.
2. **Запустить в пустой директории** — не должен ломаться, показывать пустые секции.
3. **Запустить в проекте без типичных файлов** — работает без `.env`, без `docker-compose.yaml`.
4. **Проверить EXCLUDE** — все мусорные директории исключены (build-tool wrapper, IDE, временные файлы).

**Root cause нарушений:** фокус на позитивном пространстве (что найти), игнорирование
негативного (что НЕ найти). Мышление «ну это же очевидно, скрипт не будет себя искать» —
будет, если не исключить явно.

**Связь с Rule 3.3:** верификация binding points «конфиг предполагает X, реальность Y» —
скрипт предполагает «ищу в проекте», реальность «ищу везде включая себя».

**Артефакт:** `verification/<дата>-self-test.txt` с выводом запуска инструмента на себе.

### 9. Универсальность через динамический поиск, не хардкод
Если пользователь говорит «универсальный скрипт», «для любого проекта», «не привязывайся» —
код должен искать динамически, не хардкодить структуру проекта.

**Нарушение:** захардкодил секции «1. .env файлы», «2. docker-compose», «3. Makefile» —
это привязка к конкретному проекту.

**Решение:** `grep -rlE 'паттерн'` для поиска всех файлов, затем для каждого показать
содержимое. Один раздел «Файлы с переменными» вместо трёх хардкод-секций.

**Связь с Rule 4:** требование «универсальный» → код должен искать динамически.

**Проверка:** запустить в проекте без `.env` или без `docker-compose` — скрипт не должен
ломаться или показывать пустые секции.

### 10. Исключение build-tool wrapper из поиска
Build-tool wrapper (Maven, Gradle, npm, Python) содержит бинарники и скрипты, которые
матчат паттерны поиска. Всегда исключать:

- **Maven:** `--exclude-dir=.mvn --exclude=mvnw --exclude=mvnw.cmd`
- **Gradle:** `--exclude-dir=.gradle --exclude=gradlew --exclude=gradlew.bat`
- **npm:** `--exclude-dir=node_modules`
- **Python:** `--exclude-dir=.venv --exclude-dir=venv --exclude-dir=__pycache__`
- **Go:** `--exclude-dir=vendor`

**Общий принцип:** build-tool wrapper = мусор для поиска, всегда исключать.

**Проверка:** `grep -r 'паттерн' . | grep -E '(mvnw|gradlew)'` — должно быть пусто.

**Копии репозитория и служебные папки инструментов** тоже исключать: `.claude/worktrees` (рабочие копии Claude Code), `.aider-desk`, `.idea`, `.git`. Иначе каждое совпадение повторится столько раз, сколько копий.
