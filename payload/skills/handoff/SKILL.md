# Запись состояния потоков

Поток — одна тема работы на несколько сессий («видео и расшифровки», «дизайн m3», «токены»). Файл потока — короткая запись «что в работе», без пересказа обсуждения. Знания надолго (правила, решения, предпочтения) остаются в памяти `memory/`, поток их не копирует, а ссылается.

Файлы лежат в `<проект>/.claude/handoff/` (локально, в git не идут) и в `~/.claude/handoff/` (потоки вне проекта). Хук `handoff_start.py` при старте сессии показывает список активных потоков (имя, описание, дата), хук `handoff_hint.py` подсказывает поток по ключевым словам сообщения.

## Шаги

1. Список потоков: `Glob` по `<проект>/.claude/handoff/*.md` и `~/.claude/handoff/*.md`, у каждого файла прочитаны первые 8 строк (шапка). В ответе есть имя, описание, ключевые слова, статус, дата каждого потока.
2. Темы сессии: перечисли, над чем шла работа (по сообщениям автора и вызовам инструментов). Каждую тему сопоставь с потоком по описанию и ключевым словам.
3. Для каждого затронутого потока открой его файл и обнови:
   - `## Статус сейчас` — что запущено, где результат, состояние на сегодня; статус, а не история;
   - `## Что сделать` — задачи; у каждой условие запуска (событие или результат, не «позже»); выполненные убери;
   - `## Где лежит` — пути, команды запуска, ссылки на заметки памяти и ADR;
   - `updated:` в шапке — сегодняшняя дата.
   Не затронутые потоки не открывай. В теле до 40 строк.
4. Работа без потока: каждую такую тему назови автору одной строкой. Новый поток создаётся только после его «да», по шаблону ниже. Молча потоки не заводить.
5. Статус `closed` ставится только по слову автора («тема закрыта»). Если все задачи потока выполнены, предложи закрыть, сам не закрывай.
6. Итог автору: таблица «поток — что изменено — открытые задачи». Затронутых потоков столько, сколько тем было в сессии; лишних файлов нет.

## Шаблон нового потока

```
---
name: <короткое-имя>
description: <одна фраза, что за тема>
keywords: <слова через запятую, по которым тема узнаётся в сообщении>
status: active
updated: <ГГГГ-ММ-ДД>
---
## Статус сейчас
## Что сделать
## Где лежит
```

## Правила записи

- Без секретов (пароли, ключи) и без пересказа хода разговора.
- Факт один раз: если он уже в `memory/` или ADR, дай ссылку.
- Ключевые слова: 4–8 слов и имён, которые автор реально произносит; слишком общие («проект», «код») не брать.
